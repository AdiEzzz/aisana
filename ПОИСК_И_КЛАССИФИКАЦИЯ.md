# Переработка поиска и классификации проектов AiSana

Дата: 29.07.2026. Все изменения внесены в рабочую папку, проверены сборкой и живым запуском портала с базой.

---

## 1. Почему поиск пропускал проекты

Это оказалась не настройка, а **неработающий код**. Проверено экспериментально на копии базы:

```
1) полнотекстовый поиск: ОШИБКА → column p.search_vector does not exist
2) нечёткий поиск:       ОШИБКА → function similarity(text, unknown) does not exist
```

В `src/app/api/ai-search/route.ts` было два сырых SQL-запроса:

- по колонке `search_vector` — **такой колонки в базе никогда не создавалось**, ни в одной миграции;
- по функции `similarity()` из расширения `pg_trgm` — **расширение не установлено**.

Оба запроса падали, но были обёрнуты в `try/catch` с записью в лог и пустым результатом. Пользователь ошибки не видел. В итоге выдача формировалась **единственным уцелевшим механизмом** — списком из восьми регулярных выражений, который подставлял целые категории:

```js
{ pattern: /компьютерн(?:ое|ная)? зрени|зрение|медицин|здравоохран/, categories: ["COMPUTER_VISION"] }
```

Отсюда ровно то, что вы видели: запрос «Компьютерное зрение в медицине» возвращал **все** проекты категории «Компьютерное зрение» независимо от отрасли, а запросы без слов из этих восьми регулярок не возвращали ничего.

Вторая причина — в реестре проектов и публичном API поиск шёл совпадением подстроки по трём полям (`title`, `description`, `leadName`). Такой поиск не знает словоформ: запрос «заводы» не находит текст со словом «завод», а теги, технологии, эффект и результаты не просматривались вообще.

## 2. Что построено взамен

Новый модуль `src/lib/search/` — пять файлов, каждый отвечает за свой слой.

### Морфология (`text.ts`)
Русский язык склоняется, поэтому словари хранят **основы слов**, а совпадение проверяется по началу слова: основа «завод» ловит «заводы», «заводской», «на заводах». Плюс расстояние Левенштейна для опечаток и мягкое сопоставление для коротких запросов («mine» находит «mining»).

### Справочник направлений (`taxonomy.ts`)
20 направлений из задания, у каждого — признаки на русском и английском, разделённые по уверенности:

- **strong** — однозначный маркер отрасли («карьер», «руда», «сварка», «manufacturing»);
- **medium** — сильный, но не исключительный («датчик», «маршрут», «дефект»);
- **weak** — контекстная подсказка, работает только вместе с другими.

Отдельно — короткие точные обозначения («гмк», «hr», «iot», «bim»), которые нельзя искать по началу слова.

### Классификатор (`classify.ts`)
Разбирает **все текстовые поля** проекта с разным весом: название ×3, теги ×2.5, технологии ×2, описание ×1.4, влияние и результаты ×1. Учитывает выбранную человеком категорию и справочник технологий. Проект попадает **сразу во все** подходящие направления, у каждого — коэффициент 0–100 по насыщающей кривой и объяснение с указанием сработавших слов и полей.

### Разбор запроса (`query.ts`)
Запрос сопоставляется с тем же справочником — поэтому «заводы», «производство», «manufacturing», «Industry 4.0» приводят к одному направлению. Запрос расширяется признаками найденных направлений.

### Движок ранжирования (`engine.ts`)
Два независимых сигнала:

1. **Смысловой** — совпадение направлений запроса и проекта. Именно он находит проект про дефекты сварки по запросу «промышленность», хотя такого слова в тексте нет.
2. **Лексический** — совпадение слов по **всем** полям: название, теги, технологии, описание, влияние, результаты, категория, статус, вуз, регион, руководитель.

Плюс надбавки за точную фразу и за полное покрытие запроса.

## 3. Проверка на контрольных запросах

База из 16 проектов, живой API. Результаты (балл в скобках):

**Промышленность** — «промышленность», «производство», «завод», «Industry 4.0», «industrial ai», «manufacturing» дают одинаковый набор из 5 проектов, совпадение **83 %**:

```
[64] Нейросеть для обнаружения дефектов сварки   Промышленность=92
[52] Анализ изображений конвейера                Промышленность=74
[34] Контроль СИЗ на площадке                    Промышленность=48
[34] Прогноз отказов бурового оборудования       Промышленность=49
[21] Мониторинг выбросов предприятия             Промышленность=30
```

**ГМК** — «ГМК», «mining», «mine», «металлургия», «карьер», «шахта», «руда», «обогащение», «геологоразведка» дают один и тот же набор, совпадение **100 %**.

**HR** — «HR», «персонал», «рекрутинг», «подбор персонала», «обучение сотрудников», «talent», «recruitment», «human resources» — совпадение **100 %**.

Все примеры из задания работают: «распознавание руды» относится к ГМК (67), «подбор сотрудников» — к HR (89), «анализ изображений конвейера» — к промышленности (74) и Computer Vision (90).

Показательный случай из режима отладки — проект найден **без единого совпадения слов**, только по смыслу:

```
▸ Анализ изображений конвейера
   балл 52 | смысловой 51.8 | лексический 0 | покрытие 0
   направления: Промышленность: запрос 1 × проект 74 = +51.8
```

## 4. Режим отладки

Запрос с `"debug": true` к `/api/ai-search` возвращает по каждому проекту:

```
итоговый балл: 74 | смысловой: 64.4 | лексический: 10 | покрытие: 1
поля: теги=[«контроль», «качества»] (+6); описание=[«производстве»] (+2)
направления: Промышленность: запрос 1 × проект 92 = +64.4
почему: совпали направления: Промышленность (92); слова запроса найдены: ...
```

## 6. Когда обновляется индекс

- **при сохранении проекта** — пересчитываются направления этого проекта;
- **при публикации и снятии с публикации** — сбрасывается кэш поиска;
- **после импорта из Excel** — полная переиндексация;
- **вручную** — кнопка «Пересчитать направления» в админке (68 мс на 16 проектов, для 442 ожидается 1–2 секунды).

Поисковый индекс держится в памяти и обновляется не реже раза в минуту.

**После обновления обязательно нажмите «Пересчитать направления»** — существующие проекты ещё не классифицированы.

## 7. Что стоит знать

**Векторные embeddings не используются.** Классификация построена на справочнике признаков, а не на векторной близости. Причины: результат детерминированный и объяснимый (ваши пункты 5 и 6 требуют балл и объяснение — у векторов их нет), не тратится платная квота на каждый проект, работает без интернета. Если позже понадобится улавливать формулировки, которых нет в справочнике, слой векторов можно добавить рядом — интерфейс движка это позволяет.

**Полей меньше, чем в задании.** Вы упоминали «описание проблемы», «описание решения», «MVP», «описание AI-компонента» — таких полей в базе нет. Классификатор разбирает всё, что есть: название, описание, влияние, результаты, теги, технологии, категорию. Если добавить эти поля в форму проекта, их достаточно перечислить в `FIELD_WEIGHTS` в `classify.ts` — остальное подхватится само.

**Справочник направлений — живой документ.** Если увидите, что проект попал не туда или не нашёлся, правка делается в одном файле `taxonomy.ts`: добавить основу слова в нужный уровень и нажать «Пересчитать направления». Никакого переобучения не требуется.

**Старые регулярки удалены полностью** — та самая таблица `synonymMap`, из-за которой запрос про медицину возвращал охрану труда и СКУД.
